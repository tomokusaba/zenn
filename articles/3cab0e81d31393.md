## はじめに

勉強会や社内会議、カンファレンスでは、説明の多くをスライドに載せます。しかし、後方から文字が読めなかったり、グラフの意味が色だけで表現されていたり、1 枚に情報が多すぎたりすると、内容を受け取れない人が生まれます。

スライドのアクセシビリティは特定の人だけのための後付けではありません。疲労がある人、慣れない言語で発表を聴く人、録画で資料を見る人にも理解しやすい資料になるための設計です。

本記事では、一般的なプレゼンテーション作成者を想定し、PowerPoint のアクセシビリティ チェック機能を入口に、色、文字サイズ、情報量など、明日から使える確認ポイントを整理します。

## 本記事のゴール

- PowerPoint のアクセシビリティ チェックを作成フローに組み込める
- コントラストと色覚の違いを意識した配色にできる
- 色以外の手掛かりと適切な文字サイズを使える
- 1 スライドあたりの情報量を減らせる

## まずは Accessibility Checker を実行する

PowerPoint のアクセシビリティ チェック機能は、実用的な入口です。作成中のプレゼンテーションにある、代替テキストがない画像、読み取り順序、低いコントラストなどの問題候補を検出できます。

一般的には、PowerPoint の［校閲］タブから［アクセシビリティのチェック］を開きます。対象を選ぶと、修正方法や操作の候補へ進めます。表示位置や名称は利用環境によって異なる場合があります。

Microsoft は、アクセシビリティ チェック機能が Office コンテンツに存在しうる問題を特定し、修正の推奨事項を提示すると説明しています。また、共有する前にチェックを実行することを推奨しています。

- [Accessibility guide for Microsoft 365 Apps](https://learn.microsoft.com/en-us/microsoft-365-apps/deploy/accessibility-guide?WT.mc_id=DT-MVP-5004827#increase-the-use-of-the-accessibility-checker-by-having-it-run-automatically-for-your-users)
- [Make your PowerPoint presentations accessible to people with disabilities](https://support.microsoft.com/en-gb/accessibility/powerpoint/make-your-powerpoint-presentations-accessible-to-people-with-disabilities)

:::message
Accessibility Checker は「最後に一度だけ使う機能」ではなく、レイアウトや画像が完成するたびに繰り返し実行する方が効果的です。作成途中で確認すると、修正の影響範囲を小さくできます。
:::

ここまで整えると、次はチェック機能が検出しにくい見た目の設計も確認していきましょう。

## 自動チェックだけで完成とはならない

Accessibility Checker は基本的な問題を早く見つけるための足場です。一方、Microsoft の案内では、判定対象や確認方法は項目ごとに異なり、すべてを自動で確認できるわけではありません。たとえば、組み合わせや表示条件によっては、低いコントラストを正確に判定できない場合があります。非テキスト コンテンツも含め、チェッカーだけで確認できない範囲は目視と文脈に沿って判断します。

判定対象や手動確認が必要な項目については、[Rules for the Accessibility Checker](https://support.microsoft.com/en-us/office/rules-for-the-accessibility-checker-651e08f2-0fc3-4e10-aaca-74b4a67101c1)も参照してください。

また、ツールが「問題なし」と示しても、次の点は人間の確認が必要です。

- 代替テキストが画像の目的を正しく表しているか
- グラフや図解の説明順序が発表の流れと一致するか
- グラデーションや写真の上にある文字が投影環境でも読めるか
- スライドを声に出して読んだとき、内容が自然につながるか

Accessibility Checker を通した後に、実際の表示環境と内容の意味も確認します。

:::message alert
Accessibility Checker に「問題なし」と表示されることを、アクセシビリティが保証されたことだと解釈しないでください。自動で判定しやすい項目と、文脈や意図を必要とする項目は分けて考えます。
:::

## 色は意味を伝える唯一の手段にしない

色覚の見え方、表示環境、モノクロ印刷によって色は区別できない場合があります。赤を「失敗」、緑を「成功」と表現するだけでは安全に判断できません。

WCAG 2.2 の達成基準 1.4.1「色の使用」では、色だけを、情報や動作指示、反応の促進、視覚的要素の判別に使用しないことを求めています。

> 色は、情報を伝える、動作を示す、反応を促す、又は視覚的な要素を判別するための唯一の視覚的手段にしてはならない。

— [W3C, WCAG 2.2 達成基準 1.4.1 色の使用](https://www.w3.org/TR/WCAG22/#use-of-color)

スライドでは、次のように色と別の手掛かりを組み合わせます。

| 避けたい表現 | 改善例 |
| --- | --- |
| 🔴 赤だけで「要対応」を示す | 「要対応」というラベルと警告アイコンを表示する |
| 📈 グラフの系列を色だけで区別する | 実線・破線・点線を併用し、凡例にも同じ形状を付ける |
| ✅ 選択箇所の背景色だけを変える | チェックマークや「選択中」の文字を加える |
| 🔗 リンクに色だけを割り当てる | 下線を付け、リンクであることを文字装飾でも示す |
| 📌 項目の優先度を赤・黄・緑だけで表す | 「高・中・低」や番号を併記する |

色は強調の補助として使い、ラベル、形、模様、位置、文章などと組み合わせます。

## コントラストと明度差を確認する

色を選ぶときは、前景と背景の輝度差を確認します。似た明るさの色同士は、色相が違っても見分けにくくなります。

特に次の組み合わせに注意します。

- 白背景に淡い黄色、グレー、パステルカラーの文字を重ねる
- 写真やグラデーションの上に、背景との境界を処理しない文字を置く
- 赤と緑、青と紫など、組み合わせや表示条件によって判別しにくくなる色だけを使う
- グラフの系列ごとに微妙な明度差しか付けない

背景色を分けたい場合は、別の色相だけでなく明度や濃度も変えます。特定の色の組み合わせに依存せず、必要に応じて枠線、見出し、アイコン、文字ラベルを加えます。

コントラストの目安には、WCAG 2.2 の達成基準 1.4.3 で示される 4.5:1（通常のテキスト）や 3:1（大きなテキスト）があります。Web とスライドの利用条件は異なるため、実際の投影環境や配布方法も確認します。

> 文字及び文字画像の視覚的提示には、少なくとも 4.5:1 のコントラスト比がある。ただし、大きな文字の場合は少なくとも 3:1 である。

— [W3C, WCAG 2.2 達成基準 1.4.3 コントラスト（最低限）](https://www.w3.org/TR/WCAG22/#contrast-minimum)

作成者自身の画面だけで判断せず、PowerPoint のモノクロ表示やスライドショー表示、会場の投影環境に近い画面サイズでも確認すると見落としを減らせます。

### プロジェクターの性能も考慮する

ディスプレイで見やすい配色が、そのままプロジェクターでも見やすいとは限りません。会場のプロジェクターやスクリーン、照明の状態によっては、暗い背景が黒くつぶれたり、明るい文字以外の色が識別しにくくなったりする場合があります。

色の再現性もプロジェクターの性能に依存します。プロジェクターによっては、作成時のディスプレイで選んだ色がそのまま発色せず、色相や明るさが変わって見える場合があります。似た色や淡い色で区別している場合ほど、投影後に違いが分かりにくくなるため、明度差を確保し、色以外の手掛かりも組み合わせます。

そのため、投影先が分からないスライドでは、**明るい背景に暗い文字を置くライトモードを基準に考える**のが無難です。ただし、明るい背景が必ず最適とは限りません。使用する会場で事前に確認できる場合は、実際のプロジェクターで表示してから採用する配色を決めます。

ライトモード、ダークモードのどちらを使う場合でも、文字と背景のコントラスト、色の発色、プロジェクターでの見え方、後方の席からの読みやすさを確認します。PC の画面だけで完成と判断しないことが重要です。

## 文字は「読める大きさ」を基準にする

小さな文字をたくさん置くと、会場の前後や録画の再生画面で読みづらくなります。必要な大きさは、会場、投影面、スクリーン距離、フォントの太さによって変わります。Microsoft は本文に **18 pt 以上** のフォントを使うよう案内しているため、まずはこの値を目安にし、表示条件に応じてさらに大きくします。

:::message
18 pt 以上という目安は、[Microsoft の PowerPoint アクセシビリティ案内](https://support.microsoft.com/en-us/office/make-your-powerpoint-presentations-accessible-to-people-with-disabilities-6f7772b2-2f33-4bd2-8ca7-dae3b2b3ef25)に基づきます。最終的には、実際に参加者が見る距離と画面で確認します。
:::

文字サイズ以外にも、次の点が読みやすさに影響します。

- 太さが極端に細くないフォントを使う
- 1 行を長くしすぎず、文章では短い段落に分ける
- 行間と段落間を十分に確保する
- フォントや配色をスライド間で揃える

細かな根拠は配布資料や発表者ノートへ分けます。スライドは「読む文書」ではなく、「発表の構造と要点を共有する画面」として考えます。

## 1 枚のスライドに詰め込みすぎない

複数のグラフ、比較表、長い箇条書き、注意書きが同居すると、参加者は「今どこを説明しているのか」を探しながら内容も受け取る必要があります。Microsoft のアクセシビリティ案内では、内容を読みやすく整理することが推奨されています。

私がスライドを見直すときは、各スライドに **1 枚 1 メッセージ** を設定します。これは Microsoft の仕様ではなく、私の設計方針です。タイトルを読んだだけで、そのページで伝えたい要点が分かる構成を目指します。

複数の要素を扱う必要がある場合は、次の構成が役立ちます。

1. 一覧スライド: 全体像と項目名だけを示す
2. 詳細スライド: 1 項目ずつ根拠や例を示す
3. まとめスライド: 一覧に戻り、各要素の関係を再確認する

たとえば 4 つの課題を比較する場合、最初は項目名だけを示し、続く 4 枚で 1 項目ずつ掘り下げます。小さな図を 4 分割して収めるより、参加者の注意を誘導しやすくなります。

### 説明の途中で表示位置を動かさない

アニメーションで複数の図を順に出すと、読み上げ順序や理解が複雑になる場合があります。各段階で「何が増えたか」を言葉でも説明し、重要な情報を動きだけで伝えないようにします。

## 共有前の実践チェックリスト

最後に、スライドを共有する前の確認項目を目的別にまとめます。

### 🔧 PowerPoint の機能

- [ ] Accessibility Checker を実行した
- [ ] 指摘された項目を確認し、必要なら修正した
- [ ] 組み込みレイアウトを利用し、読み取り順序を確認した
- [ ] 意味のある画像には、内容と目的を示す代替テキストを付けた
- [ ] 装飾だけの画像は、装飾として扱った

### 🎨 色・コントラスト

- [ ] 色だけで意味を伝えていない
- [ ] 重要な色分けに、ラベル、形、模様、アイコンなどを併用した
- [ ] 文字と背景のコントラストを確認した
- [ ] 写真やグラデーション上の文字が読める
- [ ] 明度差のある配色を使い、モノクロでも区別できる

### 🔠 文字・情報量

- [ ] 本文は 18 pt 以上を目安にし、必要に応じて拡大している
- [ ] 小さな注記も、表示環境で読めるサイズを確保した
- [ ] 1 枚のスライドに伝えたいメッセージが明確になっている
- [ ] 一覧と詳細を必要に応じて分割した
- [ ] 発表中に、参加者が見る場所を言葉で誘導できる

### 👥 人による確認

- [ ] スライドショー表示で、実際の投影サイズや距離を想定して確認した
- [ ] 画面をモノクロ表示しても、重要な違いが分かる
- [ ] 実際のプロジェクターでライトモードとダークモードの見え方を確認した
- [ ] 音声や読み上げだけでは伝わりにくい内容に文字や図の説明を加えた
- [ ] 可能なら、作成者以外にも一度確認してもらった

## まとめ

PowerPoint の Accessibility Checker から始めて、色、文字、情報量の順に見直します。大切なのは、次の 4 点です。

1. **Accessibility Checker を繰り返し使う**
2. **自動チェックと人間の確認を分けて考える**
3. **色だけでなく、文字や形でも意味を伝える**
4. **1 スライド 1 メッセージという方針で、一覧と詳細を分ける**

発表者にとって便利な資料と、参加者に伝わる資料は同じとは限りません。受け取る側の視点で、色、文字、順序、情報量を確認してみてください。読みやすいスライドは、誰にとっても内容へ集中しやすいスライドです♿
